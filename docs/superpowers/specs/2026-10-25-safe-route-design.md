# Безопасный маршрут по городу — дизайн

Дата: 2026-10-25
Статус: на согласовании

## Цель

Сайт, который строит пешеходный маршрут из точки А в точку Б, выбирая не
кратчайший путь, а наименее опасный при разумном удлинении — и объясняет, почему
маршрут проложен именно так.

## Допущения

Зафиксированы явно, потому что не подтверждались в диалоге:

1. **Тип опасности** — личная безопасность пешехода: тёмные и безлюдные улицы,
   проходы через парки и пустыри ночью, подземные переходы, плюс зоны, которые
   пользователь отметил сам.
2. **Не покрывается** — обстрелы и военная угроза, оперативные ЧС, статистика
   ДТП. Для таких задач нужен другой источник данных и другая модель риска; этот
   инструмент для них не подходит и честно об этом говорит в интерфейсе.
3. **Профиль** — только пеший. Авто и велосипед вне рамок.
4. **Город** — любой, где есть данные OpenStreetMap. Привязки к конкретному
   городу в коде нет.
5. **Язык интерфейса** — русский.

«Безопасность» здесь — эвристика по открытым данным, не гарантия. Данные OSM об
освещении неполные. Эта оговорка выводится в интерфейсе, а не прячется в
документации.

## Этапы

**Этап A (делаем сейчас).** Статический сайт, вся логика в браузере. Граф улиц
тянется из OpenStreetMap через Overpass API по участку вокруг точек А и Б, A*
считает два маршрута — кратчайший и безопасный. Ноль инфраструктуры, ноль
API-ключей, ноль серверов.

**Этап C (целевое).** Бэкенд на Python: FastAPI + OSMnx + networkx, граф города
предзагружен и закэширован в graphml. Снимает ограничение на размер района,
открывает дорогу тяжёлым источникам риска (открытые данные о происшествиях,
статистика) и общей базе зон опасности на несколько пользователей.

Этап A проектируется так, чтобы переезд на C был заменой одного модуля.

## Граница между A и C

Единственная точка стыка — интерфейс `RouteProvider`:

```js
// route(request) -> Promise<RouteResult>

request = {
  from:         { lat, lon },
  to:           { lat, lon },
  timeOfDay:    'day' | 'night',
  safetyWeight: 0..1,            // 0 = кратчайший, 1 = максимально безопасный
  dangerZones:  [{ type: 'circle', center: { lat, lon }, radiusM, mode: 'avoid' | 'forbid' }]
}

RouteResult = {
  routes: [{
    kind:      'shortest' | 'safest',
    geometry:  [[lat, lon], ...],
    lengthM:   number,
    durationS: number,
    riskScore: number,           // средний риск на метр, для сравнения маршрутов
    violatesForbidden?: boolean  // true, если обойти зону `forbid` не удалось
  }],
  explanation: {
    deltaM:  number,                      // насколько безопасный длиннее кратчайшего
    reasons: [{ text, avoidedM }]         // до 3 причин, по убыванию длины обойдённого
  }
}
```

Этап A реализует его в `src/route-provider/local.js`, этап C — в
`src/route-provider/remote.js` через `POST /api/route` с тем же JSON. UI, формат
зон опасности и конфиг весов риска при переезде не меняются.

## Модель риска

Стоимость ребра графа:

```
cost = lengthM * (1 + safetyWeight * risk)
risk = clamp(base + lighting + eyesOnStreet + dangerZone, 0, 5)
```

Слагаемые (день / ночь):

| Компонент | Условие | День | Ночь |
|---|---|---|---|
| base | `footway`, `sidewalk`, `pedestrian`, `living_street` | 0.0 | 0.1 |
| base | `residential`, `service` | 0.1 | 0.2 |
| base | `steps` | 0.2 | 0.5 |
| base | `path`, `track` внутри park/forest/scrub | 0.3 | 1.2 |
| base | вдоль `tertiary`/`secondary`/`primary` | 0.4 | 0.6 |
| base | `tunnel=yes` или подземный переход (`layer < 0`) | 0.8 | 2.0 |
| lighting | `lit=yes` | 0 | 0 |
| lighting | тег `lit` отсутствует | +0.15 | +0.8 |
| lighting | `lit=no` | +0.3 | +1.5 |
| eyesOnStreet | ≥3 POI в 50 м от ребра | −0.3 | −0.3 |
| eyesOnStreet | 1–2 POI в 50 м | −0.15 | −0.15 |
| dangerZone | ребро внутри зоны, `mode=avoid` | +3.0 | +3.0 |
| dangerZone | ребро внутри зоны, `mode=forbid` | ребро исключается из графа | |

POI для `eyesOnStreet`: `shop=*`, `amenity=cafe|restaurant|bar|pharmacy`,
`highway=bus_stop`, `amenity=school`.

Явный `lit=no` дороже отсутствующего тега: неизвестность не приравнивается к
худшему случаю, иначе на неразмеченных районах маршрут становится случайным.

Все числа лежат в `src/config.js` одним объектом. Крутить веса можно не трогая
алгоритм; на этапе C этот же объект переезжает в серверный конфиг.

Дефолт `safetyWeight` = 0.6.

Время в пути считается от фиксированной пешеходной скорости 5 км/ч (`steps` —
2 км/ч), тоже параметром в `config.js`.

## Интерфейс

Карта (Leaflet + тайлы OpenStreetMap) на весь экран. Панель слева:

- поля «откуда» и «куда» (клик по карте или поиск по адресу через Nominatim)
- переключатель «день / ночь»
- ползунок «быстрее ↔ безопаснее»
- кнопка «отметить опасную зону» — рисование круга на карте, выбор режима
  «обходить» или «не ходить вовсе»

На карте два маршрута: кратчайший серым (для сравнения) и безопасный акцентным
цветом. Под ними карточка: длина, время, насколько длиннее кратчайшего, и список
причин — «обходит неосвещённый участок парка, +340 м».

Стиль — по скиллу `soft-brutalist-ui`, чтобы не изобретать CSS с нуля.

## Модули

Каждый — отдельный ES-модуль, тестируется независимо.

```
index.html
src/
  main.js                   bootstrap: связывает UI и RouteProvider
  config.js                 веса риска, Overpass endpoints, лимиты, скорости
  geo.js                    haversine, midpoint, point-in-polygon, bbox
  osm-fetch.js              запрос к Overpass, кэш в localStorage
  geocode.js                поиск адреса через Nominatim
  graph.js                  построение графа, поиск ближайшего узла к точке
  enrich.js                 зелёные полигоны и POI -> признаки рёбер
  risk.js                   scoreEdge(attrs, ctx) -> number (чистая функция)
  router.js                 astar(graph, from, to, costFn)
  explain.js                сравнение двух маршрутов -> причины обхода
  route-provider/
    local.js                RouteProvider через graph + router в браузере
    remote.js               RouteProvider через POST /api/route (этап C)
  ui/
    map.js                  карта, слои, отрисовка маршрутов
    panel.js                панель управления
    danger-zones.js         рисование, хранение, экспорт/импорт зон
  styles.css
tests/
  geo.test.js
  risk.test.js
  router.test.js
  graph.test.js
  enrich.test.js
  explain.test.js
  osm-fetch.test.js
  local-provider.test.js
```

Тесты на встроенном `node --test`, `package.json` с `"type": "module"`.

Зависимостей на сборку нет: нативные ES-модули в браузере, Leaflet с CDN, тесты
на встроенном `node --test`. Сайт открывается через локальный http-сервер
(`python3 -m http.server`), потому что `file://` блокирует модули и запросы.

**Ответственности:**

- `osm-fetch` знает про Overpass и ничего про граф.
- `graph` знает про узлы и рёбра и ничего про риск.
- `risk` — чистая функция от ребра и контекста, ничего не знает про A*.
- `router` принимает функцию стоимости извне и ничего не знает про OSM-теги.
- `ui` не знает, локальный роутер под ним или удалённый.

## Данные и кэш

- Граф грузится по bbox вокруг А и Б с запасом 500 м, кэшируется в localStorage
  по ключу bbox с TTL 7 дней.
- Зоны опасности — localStorage, с экспортом и импортом JSON, чтобы разметкой
  можно было делиться файлом.
- Адреса через Nominatim, без ключа, с соблюдением лимита 1 запрос в секунду.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Overpass недоступен или лимит | понятное сообщение, автоповтор на резервном endpoint, кнопка «повторить» |
| bbox больше 100 км² | предупреждение до запроса, предложение сузить участок |
| граф больше 60 000 рёбер | предупреждение о скорости, расчёт не блокируется |
| точка далеко от любой улицы (>200 м) | сообщение «не нашла дорогу рядом», просьба переставить точку |
| маршрут не найден из-за зон `forbid` | показываем маршрут, нарушающий запрет, и явно это помечаем |
| Nominatim не нашёл адрес | предложение поставить точку кликом по карте |

## Тесты

Юнит-тесты на всё, что не трогает DOM и сеть:

- `geo` — haversine против известного расстояния, точка внутри и вне полигона,
  bbox с отступом.
- `risk` — табличные тесты: набор рёбер с разными тегами, ожидаемый score днём и
  ночью; `forbid` даёт `Infinity`.
- `router` — синтетический граф с двумя путями А→Б: короткий через неосвещённую
  тропу, длинный по освещённой улице. При `safetyWeight=0` выбирается короткий,
  при `safetyWeight=1` — длинный.
- `graph` — непроходимые дороги отброшены, двусторонние рёбра, привязка точки к
  ближайшему узлу и отказ при удалении больше 200 м.
- `enrich` — ребро внутри парка помечено `green`, POI в радиусе посчитаны.
- `explain` — причины отсортированы по длине обойдённого участка, не больше трёх.
- `osm-fetch` — текст запроса, ключ кэша, переключение на резервный endpoint
  (фейковые `fetch` и `storage`, без сети).
- `route-provider/local` — сквозной прогон на зафиксированном ответе Overpass:
  зона `forbid` на коротком пути уводит маршрут в обход; зона `forbid` на всех
  путях даёт маршрут с флагом `violatesForbidden`.

UI проверяется руками в браузере по критериям готовности.

## Что не делаем (YAGNI)

Аутентификация, серверное хранение зон (до этапа C), мобильное приложение,
пробки, общественный транспорт, промежуточные точки маршрута, пошаговая
навигация и GPS-слежение, офлайн-режим.

## Критерии готовности этапа A

1. Ввожу две точки в любом городе — получаю два маршрута на карте.
2. Ползунок безопасности реально меняет геометрию маршрута.
3. Переключение «день/ночь» меняет маршрут там, где есть неосвещённые участки.
4. Нарисованная зона `forbid` маршрут через себя не пропускает.
5. Карточка объяснения называет конкретную причину обхода и дельту длины.
6. Юнит-тесты ядра зелёные.
7. В интерфейсе видна оговорка про эвристику и неполноту данных.
